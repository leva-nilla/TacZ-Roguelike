# 0.9.7 開発再開レビュー

2026-11-21 / 基準 `adfeeaf`。P1は次の公開配布前に確認・修正する項目、P2は関連機能を触る前に優先して実機確認する項目。今回は資料の整理と調査のみで、修正・再配布はしていない。

## P1 — 公開パックの SHA-512 不一致

[Issue #1](https://github.com/leva-nilla/TacZ-Roguelike/issues/1) は 0.9.5（`8fD53Tpo`）の導入が Clumps の `invalid content hash` で止まったという報告。公開 `.mrpack` を取得し、同梱manifestとCDNから取得した実ファイルを照合した。`.mrpack` 自体のSHA-512は Modrinth API の値と一致するが、以下3件はHTTP 200で取得でき、サイズとSHA-1が一致する一方で、manifestのSHA-512は不正な桁数かつ実値と不一致だった。

| ファイル | manifest の SHA-512 桁数（正: 128桁） |
| --- | ---: |
| `Clumps-forge-1.20.1-12.0.0.4.jar` | 129 |
| `Jade-1.20.1-Forge-11.13.2.jar` | 127 |
| `Patchouli-1.20.1-85-FORGE.jar` | 129 |

[現行リポジトリのmanifest](../../tac_rogue_modpack/modrinth.index.json)にも同じ3つの値が残る。報告の有力な原因であり、Clumpsだけの修正では残り2件も問題になり得る。**次の作業:** 全43件の実データとmanifestを照合してパックを再生成し、クリーンなModrinthプロファイルで導入から起動まで確認する。今回は実データの照合を3件に絞り、ランチャーでの再現は未実施。

## P1 — パックとMODの版、サーバー配布の扱いが揃っていない

本体は `0.9.7`、リポジトリのmanifestは `0.9.6`、公開パックは `0.9.5`。公開パックには本体と起動補助の0.9.5 JARが同梱されるが、リポジトリの `overrides/` にそのJARはない。また、[MOD メタデータ](../../tac_rogue_mod/src/main/resources/META-INF/mods.toml#L26-L31)でTaCZは `BOTH` 必須なのに、[manifestのTaCZ項目](../../tac_rogue_modpack/modrinth.index.json#L534-L545)は `server: unsupported`。そのmanifestからサーバー用に取り込むだけでは必須依存が揃わない。**次の作業:** 配布対象をクライアント用と明示するか、専用サーバー用の構成を別途検証する。出荷前にパック・本体・起動補助の対応表を決め、完成した `.mrpack` の中身を確認する。

## P1 — ショップの通信形式が変わったが、チャンネル版は同じ

[0.9.5 の `OpenShopMessage`](https://github.com/leva-nilla/TacZ-Roguelike/blob/a00e0d3/tac_rogue_mod/src/main/java/com/levanilla/rogue/networking/OpenShopMessage.java) はペイロードなし。0.9.7 は [同じメッセージ](../../tac_rogue_mod/src/main/java/com/levanilla/rogue/networking/OpenShopMessage.java#L26-L40)でスタッシュ項目数と内容を読み書きするが、[通信の互換判定](../../tac_rogue_mod/src/main/java/com/levanilla/rogue/networking/TacRogueNetworking.java#L14-L22)は両版とも `5`。チャンネル版だけでは食い違いを弾けず、新クライアントが旧サーバーから空のショップパケットを受け取ると項目数を読めない。混在接続の実機確認は未実施。**次の作業:** 旧版互換を持たせないならチャンネル版を更新し、同一ビルドでショップを開けることと混在版を接続時点で拒否することを確認する。

## P2 — Public Co-op の補給箱が同じコンテナを使う

[箱を開く処理](../../tac_rogue_mod/src/main/java/com/levanilla/rogue/core/event/ItemAndLifecycleHandler.java#L90-L153)は取得記録をプレイヤーごとに持つが、補充時に共有 `ChestBlockEntity` の中身を消して詰め直す。先に開いた人の未回収分が、別の人の初回オープンで置き換わり得る。**次の作業:** 2人で同じ箱を開き、先行者の未回収分・個別の取得上限・再オープンが干渉しないか確認する。干渉する場合はプレイヤー別のコンテナか、明示的な共有取得ルールを選ぶ。
