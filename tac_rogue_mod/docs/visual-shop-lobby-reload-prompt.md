# Visual, Shop, Lobby, and Reload System Revision Prompt

## Goal
TacZ Roguelike の体験を「情報がわかりやすく、見た目で遊びたくなる」方向へ改善する。既存のゲーム進行、クエスト、パーク、ショップ、レアリティの基本仕様は維持し、UI/演出/表示/リロード挙動の不整合を整理する。

## Scope

### 1. NPC の見た目を独自化
- 現状の Villager ベースではなく、完全な独自モデル方向で実装する。
- 初期実装方針:
  - 安定性のため、まずは独自エンティティ追加ではなく、既存 Villager に専用リソースパックモデルを割り当てる方式を優先調査する。
  - OptiFine/CEM 前提にしない。Forge + 通常リソースパック + mod側描画で実現できるかを見る。
  - 可能なら `EntityRenderer` / `LayerRenderer` / client-side model を追加し、`tac_rogue_npc` タグと `npc_role:*` でロール別モデル/テクスチャを切り替える。
  - Commander: 軍服/ベレー/司令官風。
  - Quartermaster: アーマーベスト/補給ベルト/弾薬ポーチ。
  - Intel: ヘッドセット/端末/軽装オペレーター。
  - Medic: 医療バッグ/白赤系アクセント/フィールドメディック。
- 実装段階:
  1. 既存 Villager を残したまま、描画だけ専用モデルへ差し替えられるか調査。
  2. 可能なら専用 renderer/model/texture を追加。
  3. 難しい場合は独自 EntityType を追加する次段階仕様へ切り出す。
- 注意:
  - 既存セーブや既存NPCのスポーン処理を壊さない。
  - サーバー側挙動は今の NPC インタラクションを維持する。

### 2. Perk トータル効果率を実効値表示に変更
- 現在の「合計 +%」だけでは実際の確率や効果がわかりづらい。
- 表示方針:
  - Scavenger: 「ドロップ率補正 +X%」だけでなく、可能なら「実効ドロップ率 約Y%」も表示。
  - Ammo Efficiency: 「弾薬を消費しない確率 約Y%」として表示。
  - Damage, Mag Size, Reload Speed などは「最終倍率 xY.YY」形式を併記。
  - 複数パーク/修飾子/レアリティが関係する項目は、実際の計算ロジックに近い値を表示する。
- 注意:
  - 実効値が計算できないカテゴリは「合計補正」と「適用先」を明示する。
  - 誤った確定値を出すより、実計算と同期できるものだけ表示する。

### 3. Popup をフェード式からスライド式へ変更
- 表示開始時:
  - 右端からスライドイン。
- 表示終了時:
  - 右端へスライドアウト。
- 透明度フェードは最小限、もしくは使用しない。
- 複数ポップアップが重なった場合:
  - 最大3件のまま維持。
  - 縦位置は詰めて表示し、画面中央を邪魔しない。
- サイズ:
  - 現在よりさらに小さくする。
  - 幅は約180-200px基準。
  - 本文は最大2行、1行あたり短く折り返し。
  - タイトルと種別表示も小さめにまとめる。

### 4. Shop GUI をアイテム一覧型に変更
- 現状の文字リストから、クリエイティブインベントリに近い「アイコン付きグリッド」へ変更する。
- 既存インベントリ内の `SHOP` タブは廃止し、ショップ専用の独立画面として開く。
- 初期実装方針:
  - 新規 `ShopScreen` を追加する。
  - Quartermaster NPC の「ショップを開く」選択から `ShopScreen` を開く。
  - 左側にカテゴリ、中央にアイテムグリッド、右側に詳細/購入/売却情報。
  - 各アイテムは `ItemStack` を生成してアイコン表示する。
  - ホバーで名前、価格、カテゴリ、弾薬種、マガジン、レアリティを表示。
  - クリックで選択、購入ボタンで購入。
- 売却モード:
  - 既存の売却機能は維持。
  - 可能なら売却対象もグリッド表示に寄せる。
- 注意:
  - TacZ 銃/弾/アタッチメントの `ItemStack` 生成は既存 `RogueItemFactory` を優先して使う。
  - 既存の購入処理、価格、カテゴリ、在庫制限は壊さない。
  - `RogueInventoryScreen.Tab.SHOP` 関連の描画/ボタンは段階的に削除または未使用化する。

### 5. ロビーの見た目を刷新
- 現状の閉鎖空間感を弱め、基地らしい開放感を出す。
- 方向性は「近未来寄りの軍事基地」。
- 初期実装方針:
  - 中央ホールを広くし、天井高を上げる。
  - 部屋を完全に囲うより、区画/デッキ/通路で機能が見える構造にする。
  - NPCごとのステーションを視覚的にわかりやすく配置する。
  - 入口、作戦ボード、補給ラック、医療区画、情報端末、出撃ゲートを追加。
  - 明かりを増やして「地下の箱」ではなく「前線基地」に寄せる。
- 注意:
  - スポーン地点、NPC位置、既存のインタラクション導線は維持。
  - ロビー生成処理の負荷を増やしすぎない。

### 6. Auto Loader 不所持時の自動リロード修正
- 現状: Auto Loader/RELOAD_SPEED パークを取っていなくても、レアリティのマガジン補填処理により自動装填のように見える可能性がある。
- 修正方針:
  - 通常リロード完了直後の「拡張マガジン分の補填」と、時間経過の自動装填を分離する。
  - Auto Loader 系の時間経過装填は `RELOAD_SPEED` パーク所持時のみ実行。
  - レアリティ/マガジン倍率の補填は、TacZ の通常リロード完了を検出した瞬間だけ実行。
  - 空の銃が時間経過で勝手に装填されないことを確認する。

### 7. マガジン倍率/リロード倍率の実反映検討
- マガジン倍率:
  - 現状 NBT `GunCurrentAmmoCount` と補填処理で擬似的に反映。
  - 可能なら TacZ 側が参照する最大マガジン容量そのものへ反映できるか調査する。
  - 難しい場合は「リロード完了時補填 + HUD表示 + 発射時上限」の方式を正式仕様化する。
- リロード時間倍率:
  - TacZ のリロードアニメーション/実リロード完了タイミングへ安全に割り込めるイベント/API/ミックスイン対象を調査する。
  - 可能ならレアリティの `RogueReloadMult` をアニメーションと実際のリロード時間に反映する。
  - 安全なAPIがない場合、無理なミックスインでクラッシュリスクを増やさず、代替仕様を提示する。

## Implementation Order
1. Auto Loader 不所持時の自動装填バグを最優先で修正。
2. マガジン/リロード倍率のTacZ実反映可否をコード上で調査。
3. Perk 実効値表示を整理。
4. Popup をスライド式へ変更。
5. Shop 専用画面を追加し、Quartermaster 経由で開く。
6. NPC の独自モデル実現方法を調査し、可能な範囲で専用見た目を実装。
7. LobbyGenerator を軍事基地風に刷新。
8. `compileJava`、`build`、必要なら Modrinth profile へ jar 配置。

## Validation
- `./gradlew.bat compileJava`
- `./gradlew.bat build`
- ゲーム内確認項目:
  - RELOAD_SPEED/Auto Loader なしで勝手に装填されない。
  - レアリティ付き武器のマガジン表示/実弾数が矛盾しない。
  - NPCメニューが既存どおり開く。
- Quartermaster から Shop 専用画面が開き、アイコン付きで購入/売却ができる。
  - Popup がスライドイン/アウトする。
- ロビーに閉鎖感が減り、軍事基地らしい広さとNPCステーションの識別性がある。
