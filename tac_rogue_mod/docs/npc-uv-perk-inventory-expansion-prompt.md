# 実装プロンプト: NPC UV / Perk Text / Dedicated Combat Slots / Perk Sell

## 目的
NPCモデルの見た目崩れ、パーク説明の日本語表示、戦闘用スロット構成、拾得時の自動振り分けを整理する。
あわせて、パーク売却システムを導入するか判断できる状態にする。

## 対象
- NPCモデル/テクスチャ
  - `TacRogueNpcModel`
  - `TacRogueNpcRenderer`
  - `assets/tac_rogue/textures/entity/npc/*.png`
- パーク選択UI
  - `PerkScreen`
  - `PerkDefinition`
  - `ja_jp.json`
- インベントリ/ホットバー
  - `GameConstants`
  - `RogueInventoryScreen`
  - `HotbarRenderer`
  - `InventoryRuleService`
  - `RoguePickupService`
  - `ShopPlacementService`
  - 必要なら `MixinInventory` / `MixinSlot`
- パーク売却
  - 新規または既存のパーク管理UI
  - `RunManager` / `CurrencyManager`
  - 必要なら新規ネットワークメッセージ

## 仕様

### 1. NPC UV修正
- 各NPCの正面/背面/側面/頭部/胴体/装備パーツで、透明または空白のUV領域を参照しないようにする。
- 現状「後ろを見ると空白がある」ため、以下を行う。
  - モデルの `texOffs` が使うUV領域を一覧化する。
  - 128x128テクスチャ内の該当領域を全て塗る。
  - 必要なら背面専用プレート/装備プレートを追加して、後ろ姿が空白にならないようにする。
- 役職ごとに背面の識別要素を追加する。
  - Commander: 指揮官コート/階級ライン
  - Quartermaster: 補給バッグ/弾薬ポーチ
  - Intel: 通信機/ケーブル
  - Medic: 医療バッグ/赤十字
- 透明ピクセル検査を行い、モデルが参照しうるUV領域に未塗装が残らないことを確認する。

### 2. パーク選択の日本語改行
- 日本語表示時、修飾子説明が1行に詰まらないようにする。
- `PerkScreen` の修飾子説明欄は `font.split(Component, width)` で折り返す。
- 説明が長い場合は2-4行まで表示し、必要なら小さめの文字サイズまたは説明欄の高さ調整を行う。
- `ja_jp.json` の説明文に手動改行が必要なものは整理するが、基本はUI側の自動折り返しで対応する。

### 3. ホットバー/専用スロット再設計
- 銃と近接は通常ホットバー枠から独立した専用スロットとして扱う。
- 画面上の表示は以下に分離する。
  - Gun Slot 1
  - Gun Slot 2
  - Melee Slot
  - Item Slot x9
  - Ammo Slot
- 現在の「アイテムスロット6個」を9個に拡張する。
- 既存アイテムの互換性を壊さないため、内部インベントリスロット番号は慎重に再定義する。
- 必要なら既存セーブ/インベントリからの移行処理を入れる。

### 4. 拾得時の自動振り分け
- 銃を拾った場合:
  - 空きGun Slot 1/2へ優先配置。
  - 両方埋まっている場合は通常アイテムスロットへ配置する。
  - 通常アイテムスロットも満杯の場合はスタッシュへ送る。
  - スタッシュも満杯の場合のみ拾得しない/ドロップ維持にする。
- 近接武器を拾った場合:
  - Melee Slotへ優先配置。
  - 既に埋まっている場合は通常アイテムスロットへ配置する。
  - 通常アイテムスロットも満杯の場合はスタッシュへ送る。
  - スタッシュも満杯の場合のみ拾得しない/ドロップ維持にする。
- TacZの銃・近接・アタッチメントの組み合わせを楽しむ余地を残すため、余剰装備はできるだけ保管される設計にする。
- スタッシュへ送った場合はポップアップ通知を出し、プレイヤーが消失と誤認しないようにする。
- 弾薬/回復/戦術アイテムは既存ルールを維持しつつ、9個のItem Slotへ対応する。
- ショップ購入時も同じ配置ルールを使い、拾得と購入で挙動差が出ないようにする。

### 5. パーク売却システム案
パーク売却は「あると便利」だが、ローグライクの選択リスクを壊しやすい。
導入するなら以下の制限付きがよい。

- 売却はロビー限定。
- 売却価格は固定または階層依存の少額返金にする。
- ボス報酬/レア系/呪い系パークは売却不可、または低額売却にする。
- 同カテゴリを大量取得したときの整理用として使う。
- 売却後は即座にステータス再計算を行う。
- UIはパーク一覧から選択して「売却」ボタンを押す形にする。
- 誤売却防止の確認ダイアログを入れる。

推奨仕様:
- まずは「重複/不要パーク整理」の補助として実装する。
- 返金額は `100 + floor * 10` 程度の控えめ設定。
- Cursed / Overclocked / Story系は売却不可。

## 検証
- `./gradlew.bat compileJava`
- `./gradlew.bat build`
- jarをModrinthプロファイルへ反映。
- 確認観点:
  - NPCを前後左右から見ても透明/空白面が出ない。
  - 日本語パーク説明が修飾子欄で折り返される。
  - Hotbar表示でGun/Melee/Itemが分離して見える。
  - Item Slotが9個表示される。
  - 銃/近接の拾得が専用スロットへ優先配置される。
  - 専用スロットと通常アイテム枠が満杯の場合、銃/近接がスタッシュへ送られる。
  - ショップ購入時も同じスロット配置になる。
  - パーク売却を入れる場合、売却不可パークと返金が正しく動く。
