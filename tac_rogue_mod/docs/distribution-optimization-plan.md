# 配布向け残リスク最適化計画

作成日: 2026-05-15

## 目的

P0/P1最適化後に残った配布向けリスクを潰す。ゲーム内容、敵配置方針、報酬、数値バランスは変更しない。

## 対応範囲

1. ログ量の配布向け整理
2. フロア生成処理のtick分割
3. アタッチメント互換性キャッシュの古さ対策
4. FloorInstanceのUUID追跡漏れ対策
5. 三人称クロスヘア/リコイル系の描画負荷整理

## 実装方針

### 1. ログ量

- 配布版ではリコイルデバッグログをデフォルト無効にする。
- 生成やリソースリロードの通常ログは、重要な1行だけ残すかdebugへ落とす。
- 詳細計測は `-Dtac_rogue.verboseLogs=true` または既存の個別debug propertyで有効化する。

### 2. 生成tick分割

- `MapGenerator` にブロック配置を記録する生成ジョブを追加する。
- `FloorInstanceManager` のPublic/Solo入場は `PREPARING` 状態を経由する。
- 生成ジョブは1tickあたり一定数のブロック更新だけ実行する。
- 生成完了後にチェスト初期化、敵/ボススポーン、参加者テレポート、通知を実行する。
- 既存の直接 `MapGenerator.generateRoom()` は互換用として同期生成のまま残す。

### 3. アタッチメント互換性キャッシュ

- リソースリロード時に互換性結果だけでなくDB世代も更新する。
- 互換性キャッシュキーにDB世代を含め、古い世代の結果が再利用されないようにする。
- TacZ構造キャッシュ、ショップリストキャッシュ、互換性キャッシュの破棄責務を明確に分ける。

### 4. UUID追跡漏れ

- `FloorInstanceManager` に軽量auditを追加する。
- クリア判定前、途中参加補正前、インスタンス破棄前に、一定間隔で範囲内の同一instanceIdエンティティをUUID追跡へ再登録する。
- 追跡漏れが起きても、次の監査で回収されるようにする。

### 5. 三人称クロスヘア/リコイル描画負荷

- LeaWinds照準点解決をrender frame単位でキャッシュする。
- HUDクロスヘア描画と射撃同期が同一フレーム内で重複raycastしないようにする。
- リコイル詳細ログはデフォルト無効にし、必要時だけpropertyで有効化する。

## テスト計画

- `.\gradlew.bat build` が成功する。
- Public/Soloでフロア入場し、生成完了後に床へ正しく転送される。
- 生成中に参加者が抜けた場合、インスタンスが破棄される。
- チェストの中身、敵スポーン、ボススポーンが生成完了後に行われる。
- `/rogue_admin debug` などで出した敵やボスも、instanceIdが付く経路では追跡される。
- F3+Tまたはリソースリロード後、ショップ互換性ハイライトが古い結果を使わない。
- 三人称射撃時、クロスヘアとリコイルの体感を維持しつつ、ログが通常時に増えない。

## 残す制約

- 通常の古い直接生成経路は同期生成のまま残す。主経路は `FloorInstanceManager` に寄せる。
- 完全な非同期ワールド編集は行わない。Minecraftのワールド更新はサーバーtick上で実行する。
- tick分割中はプレイヤーをダンジョンへ入れない。未生成床への転送を避けるため。
