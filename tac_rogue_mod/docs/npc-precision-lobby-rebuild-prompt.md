# NPC精密化・ロビー再構成 実装プロンプト

## 背景

TacZ Roguelike Modは、ロビーNPCからクエスト、ショップ、回復、フロア選択などへアクセスし、ダンジョン階層を攻略するローグライク構成である。
現状では独自NPCエンティティ、Javaコード製ローポリモデル、役割別64x64テクスチャが導入済み。ただし、NPCの見た目はまだ簡素で、ロビーは開放的になった反面、端から奈落へ落ちる可能性がある。

この実装では、NPCの外観をより精密化し、ロビーを「開放的な軍事基地」として1から安全に再構成する。

## 目的

1. NPCをより精密な独自3Dモデルへ拡張する。
2. 役割別テクスチャを128x128へ拡張し、軍装、装備、役割差が見えるようにする。
3. ロビーを1から再構成し、開放感を保ったまま奈落落下を防ぐ。
4. 既存のゲーム進行、NPCメニュー、ショップ、クエスト、スタッシュ導線は維持する。

## NPCモデル仕様

対象ファイル:

- `src/main/java/com/levanilla/rogue/client/model/TacRogueNpcModel.java`
- `src/main/java/com/levanilla/rogue/client/renderer/TacRogueNpcRenderer.java`
- `src/main/resources/assets/tac_rogue/textures/entity/npc/*.png`

方針:

- Blockbenchモデルではなく、現状のForge Javaモデル方式を継続する。
- テクスチャサイズを64x64から128x128へ拡張する。
- Minecraftの低解像度感は残しつつ、軍事基地NPCとして判別しやすいディテールを増やす。
- 既存のNPC EntityType、メニュー処理、同期データは維持する。

共通モデル追加:

- 頭部: ヘルメットまたは帽子の土台、顎・首元の襟
- 胴体: 防弾ベスト、胸ポーチ、肩パッド、ベルト
- 腕: 手袋、袖口、左右非対称の装備
- 脚: ニーパッド、ブーツ、太ももポーチ
- 背面: バックパックまたは通信機器
- 手持ち風装備: タブレット、メディキット、補給箱などを役割別に表示

役割別シルエット:

- Commander:
  - やや高身長で直立した体格。
  - ベレーまたは指揮官用ヘルメット、胸章、タブレット/作戦資料。
  - 色はオリーブ、黒、金アクセント。
- Quartermaster:
  - 横幅があり、重装備。
  - 大型バックパック、弾薬箱、工具ポーチ、補給箱。
  - 色はグリーン、黒、タン、補給系アクセント。
- Intel Officer:
  - 細身で軽装。
  - ヘッドセット、アンテナ、タブレット、通信パック。
  - 色はネイビー、シアン、黒。
- Medic:
  - 標準体格。
  - 医療バッグ、赤十字/ピンク系マーク、白/グレー装備。
  - 色は白、グレー、赤/ピンクアクセント。

アニメーション/挙動:

- 既存のプレイヤー追従視線は維持する。
- 歩行AIは不要。
- 右クリック時のNPCメニュー導線は維持する。
- モデル部位の表示切り替えは既存の`NpcRole`で制御する。

## テクスチャ生成仕様

対象:

- `commander.png`
- `quartermaster.png`
- `intel.png`
- `medic.png`

仕様:

- 128x128 PNGとして生成する。
- JavaモデルのUVに対応した簡易スキンシートにする。
- 各役割で以下を描き分ける。
  - 顔、髪/肌色差
  - 制服色
  - 防弾ベスト
  - ポーチ/ベルト/ブーツ
  - 役割別マーク
  - 装備部分のハイライト/影
- 生成はPowerShellまたは小さなローカルスクリプトで行う。
- バイナリ画像は`apply_patch`ではなく生成スクリプトで作成してよい。

## ロビー再構成仕様

対象ファイル:

- `src/main/java/com/levanilla/rogue/world/LobbyGenerator.java`
- 必要に応じて `NpcManager.java` のNPC配置座標

コンセプト:

- 「開放的な前線軍事基地」
- 完全な密閉空間ではなく、外の空間を感じられる。
- ただし、プレイヤーが通常移動で奈落へ落ちない。
- 中央広場、4つの機能区画、外周安全帯を明確にする。

基本レイアウト:

- 全体サイズはおおむね 55x55 から 65x65。
- 中央にミッションハブ。
- 北側: 出撃/ポータルゲート。
- 南側: スタッシュ/帰還準備。
- 北東: Commander Ops。
- 南東: Quartermaster Armory。
- 北西: Intel Briefing。
- 南西: Medical Bay。

落下防止:

- ロビー全域の床を厚み2から3ブロックで生成する。
- 外周は以下のいずれか、または組み合わせで保護する。
  - 低い防壁
  - フェンス/鉄格子
  - ガラスの見えない安全柵ではなく、見た目に自然な軍事基地の防護柵
  - 外周より内側に1ブロック以上の安全余白
- 開放感を残すため、屋根は完全密閉しない。
- 端の隙間、階段、装飾の上から外へ抜けられる経路を作らない。

建築ディテール:

- 中央:
  - 作戦テーブル、ビーコン、照明塔、色分け導線。
  - ミッション開始地点とスタッシュの視認性を上げる。
- Commander Ops:
  - 作戦卓、地図、戦況スクリーン。
- Quartermaster Armory:
  - 武器ラック風ブロック、補給箱、カウンター。
- Intel Briefing:
  - 通信卓、青系スクリーン、分析端末。
- Medical Bay:
  - 医療ベッド、白/赤系アクセント、薬品棚。
- 外周:
  - 監視塔風の支柱、投光器、柵、車止め風ブロック。
  - プレイヤーの動線を邪魔しない程度に配置する。

実装上の注意:

- `buildLobby`は既存ロビー周辺を十分にクリアしてから再生成する。
- 既存NPCのメニュー機能は変えない。
- NPC座標は新レイアウトに合わせて再配置する。
- スタッシュターミナル、出撃ゲート、NPCは初回ログイン/再生成時に確実に配置される。
- ブロック数が過剰すぎてログイン時生成が重くならないよう、サイズと装飾量は抑える。
- 水や溶岩など、事故要因になる装飾は使わない。

## 受け入れ条件

- `gradlew.bat compileJava` が成功する。
- `gradlew.bat build` が成功する。
- jar内に128x128のNPCテクスチャが含まれる。
- ロビー外周から通常移動で奈落へ落ちる導線がない。
- NPC4人が新ロビーの対応区画に配置される。
- NPCの右クリックメニュー、ショップ、クエスト、回復、インテル機能が維持される。
- ビルド済みjarをModrinthプロファイルへコピーする。

## 今回の実装で変えないこと

- クエスト仕様
- ショップ品揃え/価格
- パーク効果
- ダンジョン生成
- 武器レアリティ性能
- NPC会話/メニュー仕様

## 実装順序

1. `TacRogueNpcModel`を128x128 UV前提の詳細モデルへ更新。
2. 役割別テクスチャを128x128で生成。
3. `TacRogueNpcRenderer`の体格差とテクスチャ参照を確認。
4. `LobbyGenerator`を新レイアウトへ置き換え。
5. `NpcManager`のNPC座標を新レイアウトへ合わせる。
6. `compileJava`で確認。
7. `build`でjar生成。
8. Modrinthプロファイルへjarをコピー。
